## 2. Signed URL for audio playback (backend, do this first)

- Add a backend endpoint, e.g. GET /meetings/{id}/audio-url, that:
  - Looks up the meeting's stored path.
  - Generates a short-lived signed URL via Supabase Storage's create_signed_url (check current SDK method/params before writing this — don't guess syntax).
  - Set a reasonable expiry (e.g. 1 hour) — long enough for a normal viewing session, short enough that a leaked/cached link doesn't stay valid indefinitely.
  - Returns { "url": "<signed_url>", "expires_at": "<timestamp>" }.
- The frontend calls this endpoint when the detail page loads (not the raw /meetings/{id} response) to get a playable URL for the <audio> element.
- If a user keeps a meeting detail page open longer than the expiry, the play button should fail gracefully or the frontend should silently re-fetch a fresh signed URL rather than erroring — handle at least the simple case: re-fetch a new signed URL if the audio element errors out (e.g. onError handler).
